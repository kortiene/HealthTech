🎯 Problème & Vision

Ce qu'on résout, et comment.

❌ Le problème aujourd'hui
Dans le système actuel
  • Le patient n'a pas accès à son dossier entre deux consultations
  • Les données médicales sont stockées en clair sur des serveurs tiers
  • Aucune continuité de soin : chaque médecin repart de zéro
  • Pas de standard légal appliqué (loi 2013-450 ignorée)
  • Les données circulent hors du territoire national
✅ Notre solution
HealthTech répond à chaque point
  • Le patient est propriétaire de ses données — chiffrées sur son téléphone
  • Le serveur ne voit jamais les données en clair (zéro-connaissance)
  • Le médecin reçoit les infos par QR sécurisé, à chaque consultation
  • Architecture conforme ARTCI, auditée et documentée
  • Hébergement 100 % en Côte d'Ivoire (Abidjan)

🧩 Les 3 modules

Trois composants distincts, un seul flux de données sécurisé.

📱

App Patient

Application mobile Flutter (Android/iOS)

  • Onboarding guidé (création de profil sécurisé)
  • Authentification PIN + biométrie (empreinte/Face ID)
  • Dossier médical : allergies, mesures (poids/taille), consultations, ordonnances
  • Génération de QR code sécurisé pour partager avec le médecin
  • Scanner de QR pour lire des prescriptions
  • Synchronisation cloud automatique au retour du médecin
  • Indicateur "Dernière sauvegarde" en temps réel
  • Suppression de compte et effacement local complet
  • Fonctionne hors-ligne (données locales chiffrées)
Flutter 3.24 Dart 3.5 Android iOS
💻

PWA Médecin

Application web progressive (navigateur)

  • Scan du QR patient depuis le navigateur (caméra)
  • Affichage du dossier complet : allergies, mesures, historique
  • Saisie d'une note de consultation
  • Ordonnance structurée (médicament, dose, fréquence, durée)
  • Enregistrement des nouvelles allergies (substance + sévérité)
  • Champ Médecin + Établissement / Contact sur la même ligne
  • Auto-confirmation d'une allergie à la sauvegarde
  • Zéro installation — fonctionne dans tout navigateur moderne
  • Données déchiffrées en RAM uniquement (jamais persistées)
Preact 10 TypeScript Vite PWA
☁️

Backend

Serveur zéro-connaissance (Rust + Axum)

  • Stocke uniquement des blobs chiffrés opaques (aucune donnée en clair)
  • API REST simple : GET / PUT / DELETE sur /blob/{uuid}
  • Aucune capacité de déchiffrement — même l'admin ne peut pas lire les données
  • Rate limiting par IP pour prévenir les abus
  • Journalisation sans PII (identifiants anonymes uniquement)
  • Déploiement sur infrastructure souveraine (Abidjan)
Rust Axum Tokio MinIO PostgreSQL
🔑
Crypto-Core Rust — le pilier de sécurité

Une seule implémentation cryptographique, partagée par tous les modules. Cela garantit qu'il n'y a pas de divergence entre le chiffrement côté patient et le déchiffrement côté médecin.

Algorithmes utilisés
  • AES-256-GCM — chiffrement authentifié
  • PBKDF2-SHA256 — dérivation de clé depuis le PIN
  • Nonces aléatoires — unicité garantie
Utilisé par
  • App Patient via Flutter-Rust-Bridge
  • PWA Médecin via WebAssembly
  • Tests CI — vecteurs NIST officiels
🔒 Sécurité & Confidentialité

Les principes fondateurs de l'architecture — non négociables.

🏛️

Zéro-connaissance

Le serveur ne reçoit que des blobs opaques. Il n'a aucune clé, aucun moyen de lire les données. Vérifié par des tests d'acceptation en CI.

📵

Local-first

Les données médicales vivent sur le téléphone du patient, chiffrées avec sa clé maître. L'app fonctionne entièrement hors-ligne.

⏱️

QR éphémère

Le QR code partagé avec le médecin expire après 120 secondes et est à usage unique. Après expiration, la session est révoquée.

🧠

RAM-only (PWA)

Le médecin déchiffre les données uniquement en mémoire vive. Rien n'est écrit sur le disque ou dans le navigateur.

📱

Keystore TEE

Sur Android, la clé maître est protégée par le Trusted Execution Environment (puce dédiée, isolée du système).

🗑️

Effacement garanti

La suppression de compte efface toutes les données locales et le blob cloud. Aucune trace ne subsiste nulle part.

🌍

Souveraineté des données

Infrastructure déployée uniquement en Côte d'Ivoire. Un garde-fou IaC empêche tout déploiement hors du territoire.

🕵️

Aucune fuite de PII

Le CMU et le numéro de téléphone ne transitent jamais en clair. Jamais dans les logs. Jamais sur le serveur.

✨ Fonctionnalités détaillées

Ce que chaque utilisateur peut faire dans l'application.

👤
Vue patient
Ce que le patient voit et fait

Accueil

  • Bouton "Partager mon dossier" — génère le QR immédiatement
  • Dernière consultation affichée avec date, médecin, note
  • Indicateur de dernière sauvegarde cloud (ex: "il y a 3 min")
  • Bouton scanner pour lire une prescription médecin

Dossier médical

  • Informations personnelles (prénom, année de naissance, sexe)
  • Mesures : poids (kg) et taille (cm)
  • Allergies avec niveau de sévérité (légère / modérée / sévère)
  • Antécédents médicaux
  • Médicaments en cours
  • Historique complet des consultations et ordonnances

Paramètres

  • Changement de code PIN
  • Activation/désactivation biométrie
  • Synchronisation manuelle
  • Suppression complète du compte
🩺
Vue médecin
Ce que le médecin voit et fait

Lecture du dossier

  • Scan du QR depuis la caméra du PC/tablette
  • Identité patient (prénom, âge calculé, sexe)
  • Poids et taille mis en avant pour les ordonnances
  • Alertes allergies avec code couleur (rouge = sévère)
  • Médicaments actuels pour éviter les interactions
  • Historique des consultations passées

Saisie de consultation

  • Nom du médecin + Établissement / Clinique (même ligne)
  • Contact de l'établissement (téléphone ou e-mail)
  • Note libre de consultation
  • Ordonnance structurée : médicament, dose, fréquence, durée en jours
  • Ajout d'allergies découvertes lors de la consultation
  • Enregistrement sécurisé — le patient voit les mises à jour après fermeture du QR
