2. Première installation

  1. Cloner le dépôt 
    git clone https://github.com/kortiene/HealthTech.git
cd HealthTech
  2. Créer le fichier d'environnement local — identifiants throwaway, non-sensibles 
    cp .env.example .env
    Ne jamais mettre de vrais secrets dans .env. Le fichier est gitignored mais .env.example est commité et ne doit contenir que des placeholders.
  3. Installer les dépendances Node (ADW pipeline + PWA) 
    cd adw_sdlc && pnpm install && cd ..
cd app-medecin && npm install && cd ..
  4. Pré-charger les dépendances Rust 
    cargo fetch
  5. (Optionnel) Installer le hook pre-commit — détecte les fuites avant commit 
    printf '#!/usr/bin/env bash\ngitleaks protect --staged --no-banner --redact --config .gitleaks.toml\nbash scripts/check-secrets.sh\n' \
  > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit

5. Lint et formatage

Règle absolue : toujours lancer dart format et cargo fmt avant chaque commit sur des fichiers Dart ou Rust. Le CI bloque la PR si ces checks échouent.

Lint agrégé — tous composants

just lint

Enchaîne : cargo fmt --check → cargo clippy → compliance-check → homologation-check → threat-model-check → ux-check → lowend-check.

Par écosystème

CommandeEffet
cargo fmt --check Vérifie le formatage Rust (gate CI)
cargo fmt Corrige le formatage Rust
cargo clippy --workspace --all-targets -- -D warnings Lint Rust — erreur sur tout warning
/Users/macbook/development/flutter/bin/dart format --set-exit-if-changed app-patient/ Vérifie le formatage Dart (gate CI)
/Users/macbook/development/flutter/bin/dart format app-patient/ Corrige le formatage Dart — obligatoire avant tout commit Dart
cd app-patient && flutter analyze Analyse statique Flutter — traite info comme erreur (exit 1)
cd app-medecin && npx tsc --noEmit Vérification TypeScript sans émission

8. Contrôles de sécurité et secrets

Ne jamais commiter de secret, clé, token, donnée patient réelle, ou fichier *.tfstate. Seuls les bundles SOPS chiffrés (secrets/**/*.sops.yaml) et les templates *.example sont versionnés.

Détection de fuites (obligatoire avant merge)

just secrets-lint
# ↳ gitleaks detect --no-banner --redact --config .gitleaks.toml
# ↳ bash scripts/check-secrets.sh

Tripwire résidence des données (credential-free)

just infra-residency
# ↳ bash scripts/check-residency.sh
# Échoue si un provider étranger entre dans infra/ ou si country n'est pas pinné CI

Gestion des bundles SOPS — staging / prod

La clé age privée de chaque environnement ne quitte jamais l'hôte in-country (Côte d'Ivoire). Aucun outil de déchiffrement étranger. 
# Déchiffrer un bundle vers stdout (nécessite la clé age de l'env)
just secrets-decrypt staging
just secrets-decrypt prod

# Éditer un bundle en place (re-chiffrement automatique à la sauvegarde)
just secrets-edit staging
just secrets-edit prod

Flux de secret injection

secrets/<env>/services.sops.yaml   ← chiffré, commité
        │  sops -d   (clé age in-country)
        ▼
  valeurs déchiffrées ──► Terraform : TF_VAR_*
                      └─► Ansible   : EnvironmentFile 0600 → backend (APP_ENV, DATABASE_URL, …)

9. Infrastructure et déploiement

Validation IaC — credential-free (disponible sur tout poste)

just infra-validate
# ↳ bash scripts/check-residency.sh
# ↳ terraform -chdir=infra/terraform fmt -check
# ↳ terraform -chdir=infra/terraform init -backend=false
# ↳ terraform -chdir=infra/terraform validate
# ↳ ansible-playbook --syntax-check -i infra/ansible/inventories/<env> … (dev, staging, prod)

Déploiement staging — in-country uniquement

Pré-requis : accès SSH à un nœud en Côte d'Ivoire + clé age staging.
  1. Déchiffrer le bundle vers un fichier temporaire 0600 
    sops -d secrets/staging/services.sops.yaml > /run/healthtech/staging.env
chmod 0600 /run/healthtech/staging.env
  2. Provisionner l'infrastructure 
    sops exec-env secrets/staging/services.sops.yaml \
  'terraform -chdir=infra/terraform apply -var-file=environments/staging.tfvars'
  3. Configurer les nœuds 
    ansible-playbook -i infra/ansible/inventories/staging \
  infra/ansible/playbook.yml -e env=staging
  4. Nettoyer le fichier temporaire 
    shred -u /run/healthtech/staging.env
Même procédure pour prod en remplaçant staging par prod. La mise en service complète dépend de l'issue #8 (provisionnement souverain).

10. Pipeline de livraison agentique (ADW)

Le pipeline ADW (adw_sdlc/) orchestre la livraison d'une issue GitHub de bout en bout, piloté par Claude.

Phases du pipeline

1 setup
2 classify
3 plan
4 implement
5 tests
6 resolve
7 e2e
8 review
9 patch
10 ship

Lancer le pipeline

# Commande standard
just issue <N> --runner claude --yes

# Si adw_sdlc/pnpm-lock.yaml ou pnpm-workspace.yaml sont non-trackés (cas habituel)
just issue <N> --runner claude --yes --allow-dirty

# Exemple
just issue 31 --runner claude --yes --allow-dirty

Prérequis ADW

  • ANTHROPIC_API_KEY exportée dans l'environnement (ou abonnement Anthropic actif)
  • pnpm install dans adw_sdlc/ effectué au préalable
  • adw_sdlc/pnpm-workspace.yaml doit contenir allowBuilds: esbuild: true

Ship manuel — en cas de dépassement de limite de session

Le pipeline peut atteindre la limite de session à la phase ship. Dans ce cas, récupérer le commit_message et le pr_body depuis agents/<id>/state.json et finaliser manuellement.
  1. Localiser l'agent le plus récent 
    ls -lt agents/ | head -5
  2. Lire le state pour récupérer message et PR body 
    cat agents/<adw_id>/state.json | python3 -m json.tool | grep -A10 "commit_message"
  3. Formater les fichiers Dart modifiés 
    /Users/macbook/development/flutter/bin/dart format app-patient/
  4. Vérifier flutter analyze et cargo fmt 
    cd app-patient && flutter analyze
cargo fmt --check
  5. Stager les fichiers — exclure adw_sdlc/pnpm-lock.yaml et pnpm-workspace.yaml 
    git add <fichiers modifiés>
git reset HEAD adw_sdlc/pnpm-lock.yaml adw_sdlc/pnpm-workspace.yaml 2>/dev/null || true
  6. Committer, pousser, créer la PR 
    git commit -m "<commit_message de state.json>"
git push -u origin <branche>
gh pr create --title "<titre>" --body "<pr_body de state.json>"
  7. Suivre la CI puis merger 
    gh pr checks <N> --watch --interval 30
gh pr merge <N> --squash --delete-branch

12. Dépannage

🔴 just dev-up échoue — port déjà utilisé 
# Identifier le processus occupant le port
lsof -i :5432   # Postgres
lsof -i :9000   # MinIO

# Changer le port dans .env puis relancer
echo "POSTGRES_PORT=5433" >> .env
just dev-down && just dev-up
🔴 cargo fmt --check échoue (CI rouge) 
cargo fmt
git add -u
git commit -m "style(rust): cargo fmt"

Toujours lancer cargo fmt avant de stager des fichiers Rust. Le CI bloque la PR si le formatage ne correspond pas à rustfmt.

🔴 dart format échoue (CI rouge) 
/Users/macbook/development/flutter/bin/dart format app-patient/
git add -u

Le binaire dart est à /Users/macbook/development/flutter/bin/dart. Toujours formater avant de stager des fichiers Dart.

🔴 flutter analyze — curly_braces_in_flow_control_structures 
// ❌ Mauvais
if (condition) doSomething();

// ✅ Correct
if (condition) {
  doSomething();
}
🔴 flutter analyze — prefer_const_constructors 
// ❌ Mauvais
TextScaler.linear(1.5)

// ✅ Correct
const TextScaler.linear(1.5)
🔴 cargo test — imports rustfmt non conformes

rustfmt exige le style bloc pour les imports multi-éléments : 

// ❌ Mauvais
use crypto_core::{decrypt_record, encrypt_record,
    generate_master_key, NONCE_LEN};

// ✅ Correct
use crypto_core::{
    decrypt_record, encrypt_record, generate_master_key, NONCE_LEN,
};
🟡 Pipeline ADW — could not parse JSON from agent output

La session Claude a expiré pendant la phase ship. Suivre la procédure de ship manuel (section 10) : lire agents/<id>/state.json, formatter, stager, committer, pousser, créer la PR.

🟡 osv-scanner non trouvé 
# macOS
brew install osv-scanner

# Linux
wget -q https://github.com/google/osv-scanner/releases/latest/download/osv-scanner_linux_amd64 \
  -O /usr/local/bin/osv-scanner && chmod +x /usr/local/bin/osv-scanner
🟡 sops -d échoue — clé age absente

La clé age privée de l'environnement cible est hébergée in-country (Côte d'Ivoire) et ne doit jamais quitter l'infrastructure souveraine. Contacter l'opérateur in-country pour accès. Pour le développement local, utiliser .env (throwaway) — aucune clé age n'est nécessaire.

🟡 flutter build appbundle échoue — Android toolchain absent 
flutter doctor   # diagnostiquer l'environnement
# Installer Android SDK via Android Studio ou sdkmanager
flutter config --android-sdk /path/to/android-sdk

Le build APK n'est pas nécessaire pour le développement local. Il est produit par le CI.
